# Plan Changes

> Every scope change after the CP0 freeze requires an entry here.
> Format: date · CP · change · rationale · parity rows affected.

| Date | CP | Change | Rationale | Rows affected |
|---|---|---|---|---|
| 2026-10-01 | CP0 | Plan frozen at v1. No changes yet. | — | — |
| 2026-10-01 | CP5 | Geodesy upgraded spherical→WGS84 ellipsoidal. | Mandated by COR-003 ("never compare raw WGS84 as planar metres"). Legacy haversine was mislabelled WGS-84. Measured cost recorded (≤1.11% on sub-km baselines). | COR-003 |
| 2026-10-01 | CP5 | New classification bands added (SEA_CLUTTER / LOW_CONFIDENCE / UNRESOLVED). | Mandated by COR-011; legacy emitted only 3 of 7 states. Bands calibrated so the golden run stays stable; deltas documented. | COR-011, COR-012 |
| 2026-10-01 | CP6 | Pipeline uses a stage CALLBACK, not a generator. | A generator cannot both yield live stages and return the result document the API needs. Callback streams events in real time and returns the evidence dict. No requirement change. | OPS-002, EVD-001 |
| 2026-10-01 | CP15 | Wake detection: Radon arm-pair → polar-ray arm-pair. | The Radon variant was measured to be **insensitive to wake strength** (identical z across a 14 dB sweep) because summed projections are dominated by per-row background and per-angle normalisation cancelled the signal. Switched to direct ray sampling, which measures arm contrast where it physically is. Recorded rather than silently rewritten. | ADV-004, ADV-005 |
| 2026-10-01 | CP15 | Wake confidence semantics clarified. | Confidence is bounded evidence strength, not a probability; it saturates because a brighter arm does not make the geometry more certain. Angular recovery tolerance documented at ±10 deg. | ADV-005 |
| 2026-10-02 | post-CP15 | **Scope widened: the synthetic scene generator is deleted, not gated.** The previous plan removed DEMO from the product while keeping a generator alive for tests behind `Settings.allow_synthetic_scenes`. That flag is now removed, `backend/darkfleet/demo.py` is deleted, and the tests read a checked-in COG fixture through the production pipeline instead. | A synthesiser kept alive for tests is still a synthesiser: leaving it importable is what forced the guard flag to exist, and the guard flag is what kept a fabricated-observation capability one env var from the product. The tests needed a *raster*, and a checked-in GeoTIFF is the honest way to get one — real data, no credential, no network, and the production CFAR/mask/correlation/persistence code still in the loop. | EVD-006, EXP-006, TST-004 (all resolved by removal) |
| 2026-10-02 | post-CP15 | **Second implementation deleted:** `server.ts` (375-line Express API) plus 35 unreachable frontend modules and 4 test files (89 tests). `npm run dev` is now `vite`, `npm start` is `vite preview`. | `server.ts` reimplemented the entire analytical pipeline in TypeScript and *defaulted to DEMO* (`runtimeMode = 'DEMO'`), so the default way to launch the project produced invented data — while contradicting `vite.config.ts`, which already proxied `/api` to Python, and while Docker never ran it at all. UI-037's "delete legacy files after parity" gate was satisfied, so the whole unreachable tree went as one batch. | UI-037, UI-038, API-011, UI-018 |
| 2026-10-02 | post-CP15 | **Three new requirement IDs assigned after the freeze:** GEO-001 (named marine regions, already shipped), GEO-002 (`GET /api/revisit`, measured SAR acquisition planning), GEO-003 (vertical datum safety). | Each closes a specific way the tool could mislead: a bare coordinate pair reads as less than it is (GEO-001); a predicted pass would read as a measurement (GEO-002); an unlabeled height reads as an altitude that SAR never measured (GEO-003). They sit **outside** the frozen 201-ID count, and the header count is deliberately left alone. | GEO-001, GEO-002, GEO-003 (new section in both this file's sibling parity matrix and the requirements doc) |
