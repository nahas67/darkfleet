## Operational limits and responsible release stance

1. **Science:** A GeoTIFF intake remains `IMPORTED_NOT_ANALYZED` unless real canonical pipeline executes. An operator declaration of polarization/RTC/calibration cannot authenticate acquisition. `SAR_UNMATCHED` means only no accepted AIS match, never illicit activity or motive. Independent live AIS/SAR calibration, association ground truth, uncertainty validation and adversarial false-alarm evaluation remain absent.
2. **Sources:** Live dataset inventory returned six entries, only Natural Earth coastline usable (**CHECKSUM_UNRECORDED**); EEZ and high-seas WFS absent, WPI blocked by trusted-TLS transport, GEBCO absent. `/api/providers/health` timed out within a three-second probe; this does not establish remote source outage. Legitimate map provider fallback is preserved.
3. **Security:** Locally bound API has no user authentication; externally reachable deployments require an authenticating proxy. Windows symlink privileges prevented some tests; concurrent reparse-point TOCTOU is not fully defeated. AIS Parquet locks are same-process only; cross-process consistency requires an interprocess transaction design. Provider failure, successful and legacy stage, direct STAC log secrets are redacted with explicit canary evidence (`77eb6b5`, `0948bf5`, `0bf2417`); arbitrary unknown credential patterns cannot be universally guaranteed safe.
4. **Performance:** Synthetic CPU-backed 100/1k/5k/10k throughput and real idle-globe browser RAF were measured separately. Six 10k label arbitration samples each used under 100ms per-thread CPU (47ms aggregate). Following `d4e667a`, 10k display-state computation improved from 92.91–137.61ms median in isolated baseline runs to 39.76–42.59ms median post-change, full output SHA identical. Representative concurrent **whole 10k CPU pipeline** decreased **247.12→147.62ms** (one-shot, contention-dependent), so sub-100ms end-to-end is unproven. Active-10k-AIS Cesium FPS/VRAM/leak drift and long-run validation are unverified. Large Vite bundle is an advisory, not proven latency cause.
5. **Runtime recovery:** No fully exercised job cancellation/stale-interrupted-job recovery contract is present. Known key/token patterns in producer-controlled non-failure stage messages now pass explicit redaction canaries, but arbitrary unknown secret formatting still requires operational logging policy. Isolated GeoTIFF actual Chrome/API restart and temporary case/mission API restart passed; restart of every mutable settings/control in the real browser was not completed.
6. **Evidence harness:** Vite dev source hashes and actual Chrome DOM were observed, but an intermediate production manifest claimed a dirty older HEAD even though its digest matched the bytes. The fail-closed reproducible `build-tools/release_build_verifier.py` checks Git HEAD, clean tree, built and served meta+manifest HEAD, production mode, source contract hash, sorted per-file byte digest, and byte-identical served assets. Because recording its result **in a new Git commit** changes the HEAD that was verified, release acceptance must capture the verifier output for the **final committed source HEAD** after this document is committed. A pass at an older HEAD is no longer a pass for a newer build.

### Matched-source 10,000-contact CPU optimization

`build-tools/ais_10k_cpu_benchmark.ts` independently exercises the existing `aisRenderer.perf.test.ts` fixture outside Vitest: 10,000 vessel series, **50,000 deterministic synthetic AIS-format observations**, five warmups and 25 timed ticks per process, separate EXACT minute 8 and INTERPOLATED minute 10. First pre-change standalone repeats demonstrated the original 100 ms whole-path target was **not consistently met**, including an exact worst 147.42 ms and interpolated median 107.58 ms in separate quiet-process runs. No global cache, loss of measurements, fabricated kinematics or altered selected contacts.
