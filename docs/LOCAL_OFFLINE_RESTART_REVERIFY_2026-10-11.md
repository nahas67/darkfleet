# Local/offline restart and egress re-verification — 2026-10-11

## Scope, data and methods

This verification uses the existing FastAPI application factory and **new,
independent `TestClient` lifespans** against a unique pytest `tmp_path`
configured as `Settings.data_dir`. No existing `data/` database, archive,
provider credential, download, user workspace, or scan was read or changed.
Temporary SQLite operator records were created by the real HTTP routes. A
deliberately malformed local `scans/INVALID-SOURCE.json` contains only
`{not-json` and can never be interpreted as sensor data. No fake persisted
REAL scan, SAR detection, AIS observation, or provider result was created.

Owned artifacts:

- `backend/tests/test_restart_workflows_reverify.py`: executable regression.
- `docs/LOCAL_OFFLINE_RESTART_REVERIFY_2026-10-11.md`: evidence and limits.

## Attempted versus actual network egress

The test wraps `httpx.get/post`, the synchronous/asynchronous HTTPX network
transports, `socket.getaddrinfo`, `socket.socket.connect/connect_ex`, and
`socket.create_connection` before exercising FastAPI. Public addresses are
rejected **before** DNS or network transport. The existing suite-wide socket
guard remains active independently. An explicit `blocked.invalid` DNS probe
proves the test's recorder actually detects and blocks a deliberate attempt.
The ASGI `TestClient` transport is in-process and never crosses the network.

| Backend path(s) executed | Declared external reachability | Observed attempted egress | Real public traffic |
| --- | --- | --- | --- |
| Case/notes/geometry/views/missions/reports/analyst, including restarts and corruption paths | None necessary | **0** | **0; transport blocked** |
| `GET /api/providers/health` | Planetary Computer, Earth Search, Copernicus CDSE, local AIS archive | **3 intercepted HTTPX calls** to `planetarycomputer.microsoft.com`, `earth-search.aws.element84.com`, and `stac.dataspace.copernicus.eu` | **0; intercepted before transport** |
| Local AIS health probe | Local archive; optional live AIS credentials are configuration only here | **0** | **0** |
| Frontend basemap sources | Declared keyless **OpenStreetMap** (`tile.openstreetmap.org`) and **Esri World Imagery** (`server.arcgisonline.com`), optional Cesium ion (`assets.cesium.com`) in `src/globe/mapSources.ts` | **NOT_RUN** (browser not exercised) | **NOT_RUN** |
| Live STAC search, stream AIS, raster/tiles and map provider fallback | Legitimate provider-backed workflows but out of this offline route exercise | **NOT_RUN** | **NOT_RUN** |

**Provider-health result is not an uptime measurement.** The provider code
attempted declared probe URLs, intercepted HTTPX raised connection failures,
and status was appropriately `UNAVAILABLE` (local AIS `NOT_CONFIGURED`).
The fallback OSM/ESRI source declarations remain intact; observing saved
map-source identifiers in SQLite does not prove tile fetches or failover.
Neither frontend basemap traffic nor websocket traffic was exercised.

## Remaining validation limits

This suite proves sequential restart durability with fresh lifespans, not a
process crash during SQLite commit, corrupt entire database recovery,
concurrent writers, production authentication, or OS power-loss durability.
Tests do not establish satellite data correctness or live sensor coverage.
No database migration/recovery was changed. An operational operator-owned
REAL scan would be necessary to execute the watchlist→rule→trigger→ack happy
path without manufacturing a sensor observation. Browser-based actual
OSM→ESRI fallback, external network credentials, and any persisted settings
control would require separate explicit verification.
