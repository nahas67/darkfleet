## Scoped repair and safety discrimination

Only `backend/darkfleet/jobs/runner.py` changed in production:

1. A new job holds a **kernel file lock** on `state/jobs/DF-xxxx.lock` for the lifetime of its in-progress work; it is released at terminal state or by the OS if the worker process terminates. The marker file is retained. Uses Windows `msvcrt.locking` on this verified host and POSIX `fcntl.flock` by branch (POSIX execution NOT_RUN).
2. At state restoration, a nonterminal job with an existing, **freely acquirable owner lock** is marked `FAILED` with an explicit `InterruptedError`. The original history remains unchanged, a single terminal failure event is appended, `failed_at` identifies the next incomplete canonical stage, `finished_at` is the recovery timestamp, and durable JSON is updated. No stage work is rerun, no `COMPLETE` is invented, no sensor evidence is produced.
3. A nonterminal job whose lock is **held elsewhere** remains nonterminal and is returned with an in-memory `ACTIVE_ELSEWHERE` diagnostic rather than being falsely marked failed. This independent reader has no live cross-process event subscription; clients should use the actual owning server. A pre-lock-protocol job without a marker is **ambiguous**: it retains its actual stage/history and gets an in-memory `OWNERSHIP_UNVERIFIED` diagnostic. Its JSON is not modified. Neither case is claimed recovered. `ScanRunner.wait_for` returns `False` immediately for these unowned jobs, `subscribe` raises `JobNotOwnedError`, and `GET /api/scans/{id}/events` returns **HTTP 409 / SCAN_STREAM_UNAVAILABLE** with the precise ownership status instead of emitting a fictitious terminal event or hanging until the SSE timeout. `GET /api/scans/{id}` still provides the original stage/history and ownership warning.
4. Fresh submit refuses to overwrite a scan ID whose lock cannot be acquired. A local thread-start failure now records a genuine `FAILED` event and releases the lock instead of leaving an ownerless `QUEUED` job. Completed and already-failed jobs remain untouched on reload. Password/signed-token stage-detail redaction introduced earlier is preserved.

The new `backend/tests/test_job_interrupted_restart.py` verifies a copied real job-state snapshot, API `GET` source/status/provenance, `/events` chronological SSE and terminal replay, `wait_for(0)` completion, durable restore twice without duplicate terminal events, active-writer lock discrimination and API 409, legacy no-marker preservation and API 409, and a rejected worker-thread start. The generator is deliberately labelled as a **local test generator with fixture candidates**; it does not create source imagery, use network providers, or assert scientific acquisition.
